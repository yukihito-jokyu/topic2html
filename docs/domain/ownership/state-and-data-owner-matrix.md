# 状態・データの責任分担表

## 目的と読み方

この表は、各状態またはデータを変更する責任を持つ機能を一つに定める。「Owner（責任を持つ機能）」は、その状態の意味と変更規則を定義する担当であり、保存先を持つ実装担当だけを意味しない。単一Ownerにする理由は、同じ状態を二つの機能が別々に更新して矛盾することを防ぐためである。

このTaskでは責任境界だけを定める。具体的な認証、再試行、公開状態遷移、保存処理、画面、ネットワーク隔離方式は各Ownerの後続詳細設計で決める。

## Owner間の受渡し境界

- L3からL4へ渡すのは、成功しHTML形式の機械検証に合格した生成結果と、その系譜を特定する情報だけである。失敗試行の詳細内部ログや失敗試行を版として渡さない。
- L4からL5へ渡すのは、`HtmlId`と、そのHTML全体に検証済み版が存在するという適格性である。L5はこの情報を使って、独立した`PlacementId`をHTML全体の現在の掲載先として初回設定できるか判断する。タグ・配置の過去履歴や版ごとの状態を渡さない。
- L4からL6へ渡すのは、`HtmlId`に属する検証済み`VersionId`の存在と読取りである。L6は公開版参照を所有するが、版本文・修正系譜を変更しない。
- L2からL3〜L6へ渡すのは、操作主体が管理操作を許可されたかという判断である。Googleのトークン、セッション値、メールアドレスなどの認証情報を他Ownerのドメイン状態へ複製しない。
- L5からL6へ渡すのは、HTML全体が現在参照するタグと`PlacementId`の読取りである。`PlacementId`は同じ掲載先を複数のHTML全体で共有できるが、L6の公開版切替は、その参照値を変えず巻き戻さない。

## 競合を防ぐ共通規則

1. 同じ状態を複数Ownerが正本として保存・更新しない。必要な場合はOwnerが提供する後続のInterfaceを使う。
2. L4の不変版とL6の公開版参照を混同しない。L4は履歴の正本、L6は現在公開する一版を指す正本である。
3. L5のタグ・配置を版の属性として複製しない。これらはHTML全体の現在状態であり、公開版切替で維持する。
4. L3の失敗試行をL4の検証済み版として扱わない。失敗を保持する目的と、閲覧・公開できる内容を保存する目的は異なる。
5. L2とL6の境界を混同しない。L2は管理者かどうかを判断し、L6は生成HTMLを隔離して表示する。どちらも必要だが、認証情報の隔離を二重に所有しない。
