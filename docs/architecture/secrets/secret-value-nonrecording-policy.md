# 秘密値の非記録・受渡し規則

## 1. 目的と対象

秘密値とは、知る者にアプリ、利用者、外部サービス、または管理用Databaseへ接続・なりすまし・改ざんの能力を与える値である。本書は、秘密値を設計書、Log（プログラムや運用処理の実行記録）、Fixture、Command引数、継続的インテグレーションの保存物へ残さず、許可されたServer処理だけへ渡す規則を定める。値を一度でも記録物へ複製すると、元の保存場所より閲覧者・保持期間・複製数が増え、後から完全に回収できないためである。

対象は、Google OAuthのClient secret、通常Server用とMigration Runner用のDatabase接続文字列、Session署名鍵、および将来追加する同等の権限を持つ値である。正確な一覧、利用主体、露出面は[設定情報の分類台帳](../configuration/configuration-registry.md)を正本とする。本書は秘密値の発行、保存製品、注入方法、更新運用を選定しない。秘密値を読んだ処理がどの製品へ接続するかを実装することも対象外である。

## 2. 禁止する記録と、代わりに残す情報

| 記録先 | 秘密値について禁止する内容 | 残してよい代替情報 | 必要な理由 |
| --- | --- | --- | --- |
| 設計書・README・コメント | 実値、値の一部、Base64などの可逆符号化値、接続文字列、コピー可能な例。 | 識別名、機密区分、読む主体、露出禁止面、形式検証の規則。 | 文書はレビュー、検索、配布で広く複製される。識別名だけなら設定責務を説明でき、接続能力は複製しない。 |
| Application Log・監査Log・例外表示 | 実値、HTTP Header、Cookie、URL Query、接続先を含む接続文字列、秘密値を含み得る構造体の全体出力。 | 識別名、処理段階、存在/形式/照合の失敗分類、相関用の非秘密な要求識別子。 | Logは障害調査に必要だが、運用者・集約サービス・保存期間が増える。失敗原因を安全な分類へ縮約する。 |
| Command引数・Process一覧 | `--secret=値`、Database URL、Session鍵、Shell環境変数を展開した値。 | 値を含まない設定名、値を伏せる入力機構の利用結果、終了状態。 | Command引数はProcess一覧、履歴、診断出力から他ユーザーや監視に見える可能性がある。 |
| Test Fixture・Mock・Snapshot | 実環境の秘密値、その断片、実Databaseや実Googleへ接続できる値。 | `TEST_*`の決定的な代替値、拒否を確認する明示的な無効値、識別名。 | FixtureはRepositoryとCI Artifactへ複製される。Testの再現性は必要だが、実接続能力は不要である。 |
| CI Artifact・Build出力・Browser bundle | 実値、Build時に展開された秘密設定、診断用Dump。 | 秘密検出の合格/不合格、検査したFile名、秘密値を含まない要約。 | ArtifactとBrowser bundleはServerのアクセス制御外へ配布・保管され得る。Build成功は秘密非露出の証明にならないため、別検査が必要である。 |
| 管理画面・公開画面・生成HTML | 実値、秘密値を復元できる暗号文、署名済みの管理用資格情報、秘密値を読める操作窓口。 | 設定が利用可能かという真偽、利用者操作に必要な安全な失敗理由。 | 管理者向け画面でもブラウザへ到達した値は端末・拡張機能・画面共有へ露出し得る。生成HTMLは未信頼なので、公開可能設定も最小にする。 |

「伏せ字」やHash（元の値から一定の計算で得る短い値）は、秘密値の記録を許可する方法ではない。伏せ字は実装の誤りで全値を出すおそれがあり、Hashは低い候補数の値を照合できる場合がある。秘密値の有無を示す必要がある場合は、値と独立した`configured`（設定済みか）という真偽だけを記録する。

## 3. 受渡し規則

1. 秘密値は、台帳で利用主体として指定されたServer処理だけが実行時に読む。実行時とは、必要な処理を始める直前から処理終了までであり、Build、Browser、生成HTML、通常のTest Fixtureへ複製する時点を含まない。
2. 秘密値を読む処理は、値が存在し、空でなく、想定形式であり、別の露出面から渡された値ではないことを検証する。検証失敗時は対象処理を停止し、秘密値を補完値、既定値、公開設定から推測して続行しない。誤った接続先や弱いSession状態で稼働させないためである。
3. Server内でも、通常の管理用Database接続とMigration用Database接続は相互に渡さない。Migration用接続は保存構造を変更できるため、通常Serverへ常時渡すと最小権限の境界が崩れる。
4. Serverから管理画面、公開画面、生成HTMLへ秘密値を返さない。秘密値を必要とする外部要求はServerが実行し、表示面へは成功・失敗の安全な結果だけを返す。特に生成HTMLからアプリ内部へ戻る経路は設けない。これは`TB-06`が定める隔離条件である。
5. 生成HTMLの外部通信を一律に禁止しない。ただし、生成HTMLが行う外部要求へ、アプリが保持するGoogle資格情報、Database資格情報、Session、管理データを自動付与してはならない。許容する通信と資格情報非付与を両立するためである。

## 4. Migration専用秘密値とTimeoutの安全条件

`MIGRATION_DATABASE_URL`はMigration Runnerだけが実行時に読み、Command引数、Log、CI Artifactへ出さない。接続文字列は資格情報を含み得るため、Database Hostだけを切り出して安全とみなすこともしない。

Migrationの排他印であるPostgreSQL Advisory Lockを待つ時間は、Database側の`MIGRATION_DB_LOCK_TIMEOUT=10s`を、呼出側の`MIGRATION_CORE_LOCK_TIMEOUT=15s`より短くする。前者はDatabaseがLock待機を中止する上限、後者はMigrationライブラリ呼出側が待つ上限であり、同じ種類の時間制限ではない。10秒 < 15秒により、取消不能な呼出側の待機より先にDatabaseが要求を失敗させ、後続のMigrationを実行しないことを確認できる。`MIGRATION_STATEMENT_TIMEOUT`はSQL文の実行時間を制限する任意値であり、Lock待機の代用にしてはならない。

この関係を変更する後続Taskは、両方を有限の正の時間とし、Database側 < 呼出側を守り、競合したIntegration Test（複数の実行処理が同じ資源を争う状況を再現する結合検証）で、Database側のTimeout後にMigrationが1件も実行されず接続が閉じられることを確認する。根拠と詳細な失敗経路は[ADR-0005](../decisions/adr-0005-migration.md)に従う。

## 5. Test用代替値の条件

Test用代替値は、形式検証、未指定時の拒否、権限拒否、失敗表示を検証するためにだけ使う。値ごとに、実秘密値と異なること、実外部サービスまたは実Databaseへ接続できないこと、Test以外の起動で読み込まれないことを確認する。たとえばDatabase URLが必要なTestは、隔離した一時DatabaseやTest Double（実物と同じ操作境界だけを再現する代替実装）を使い、共有環境の接続文字列をFixtureへ保存しない。

Test用代替値を文書へ例示する場合も、実サービスのClient ID、実Host、実ドメイン、実利用者のメールアドレスを連想させる値を避ける。代替値が実接続できるかどうかは値の文字列だけでなく、Test実行環境のNetwork・資格情報にも依存するため、後続実装は接続拒否をTestで確認する必要がある。

## 6. 漏えいが疑われる場合の停止と引継ぎ

秘密値が文書、Log、Fixture、Artifact、画面、生成HTMLへ出た可能性を検知した処理は、その値を含む出力の追加生成を停止し、値を再表示して調査してはならない。検知記録には、秘密値ではなく識別名、露出面、検知時刻、対象の保存先、隔離した操作、追加出力を止めた理由を残す。これにより、原因追跡に必要な事実と、値を再拡散しないことを両立する。

値の失効、置換、保存物の削除、外部サービスへの連絡は、権限と運用手順を持つ後続Ownerが決める。本Taskはそれらを実行しない。本書を入力として受け取るTaskは、具体的な秘密管理方式を選ぶ前に、台帳の利用主体・露出面・記録可否を満たすことを確認しなければならない。
