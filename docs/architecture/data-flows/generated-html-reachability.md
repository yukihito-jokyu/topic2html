# 生成HTMLの到達可否境界

- 対象作業: `L1-M1-S1`
- 状態: 独立レビュー完了・コミット承認待ち
- 根拠: `BR-021`、`NFR-002`、`NFR-003`、`AC-019`、`AC-029`

## 1. 到達の定義

この文書で「到達できる」とは、生成HTMLまたは生成HTMLから起動した処理が、対象の情報を読み取る、変更する、対象へ権限を伴う要求を送る、または別の主体を経由して同じ結果を得られることをいう。Web上の場所識別子や通信網上で接続を試みられるだけではなく、意味のある読取・変更が成功するかを判定する。直接経路だけを閉じて代理処理から到達できる状態を防ぐため、この定義が必要である。

「到達不可」は、採用技術が次の結果を保証することを意味する。

- 対象情報を生成HTML実行領域へ最初から渡さない。
- 生成HTMLから対象を読み書きする権限や資格情報を与えない。
- 管理制御領域の代理機能を使って同じ結果へ到達させない。
- 管理者プレビューと匿名公開の両方で同じ禁止結果を保つ。

## 2. 到達可否表

| 識別子 | 生成HTMLからの対象 | 判定 | 許可・禁止の正確な意味 | 必要な理由 |
| --- | --- | --- | --- | --- |
| `RA-01` | 表示対象として渡された自分自身のHTML本文 | 許可 | 表示・実行に必要な範囲で利用できる | 生成HTMLを閲覧するという目的そのものだから |
| `RA-02` | 表示に不可欠で秘密でない最小の表示用情報 | 条件付き許可 | 後続設計が項目ごとに必要性を示し、管理上の判断元から切り離した、管理操作能力を持たない値だけ。管理者、ログイン継続状態、非公開状態を示す情報は含めない | 公開可能な値を渡す場合も、不要な管理データや管理権限を表示領域へ持ち込まないため |
| `RA-03` | アプリ管理外の外部サイト・外部サービス | 許可 | 外部との通信を一律禁止しない。個別の外部側拒否や失敗まで成功保証はしない | `NFR-003`を満たしつつ、外部サービスの都合をアプリ保証にしないため |
| `RA-04` | 外部通信時の閲覧者接続元情報・利用環境情報 | 外部側から観測され得る | 外部サービスが通常の通信で得る情報や、生成HTMLが要求へ含めた内容を記録する可能性を受容する | `RISK-006`を隠さず、アプリ秘密との違いを明確にするため |
| `RA-05` | 管理者のログイン継続状態、Google資格情報、管理認可情報 | 禁止 | 読取、利用、外部送信、管理操作への転用をすべて不可とする | 管理者プレビューからの権限奪取を防ぐため |
| `RA-06` | 管理画面の文書構造、画面状態、利用者側の管理用保存領域 | 禁止 | 親画面の内容読取・操作、管理用の画面側状態の参照を不可とする | 画面経由で資格情報や管理操作へ迂回到達させないため |
| `RA-07` | 生成、タグ、配置、公開などの管理操作 | 禁止 | 読取専用の表示を装った変更も含め、生成HTMLを操作主体として受け付けない | 生成HTMLは管理者本人ではないため |
| `RA-08` | 管理操作用の窓口、認証・認可処理、内部の責務間操作窓口 | 禁止 | 資格情報なしの試行だけでなく、管理者の権限が自動付与された要求を成功させない | 管理制御領域への逆向き経路を閉じるため |
| `RA-09` | 管理用永続化と、その接続資格情報 | 禁止 | 直接接続、汎用代理読取、書込、一覧、推測可能な参照による取得を不可とする | 保存層から管理データを抜き出す迂回を防ぐため |
| `RA-10` | 非公開HTML版、版履歴、生成試行、失敗記録、詳細内部ログ | 禁止 | 表示対象として解決済みの1版以外を取得できない。公開・プレビュー資格のない情報を列挙できない | 未公開情報と内部情報を守るため |
| `RA-11` | タグ・配置・公開状態を決定する管理データ | 禁止 | 値が公開可能かにかかわらず、管理上の判断元を読書きできない。表示に不可欠な公開値がある場合は、`RA-02`の表示用情報として管理データから切り離す | 公開情報の表示を、管理データや管理操作への到達許可へ拡張しないため |
| `RA-12` | Codex app-serverの接続機能と資格情報 | 禁止 | 生成HTMLがアプリの資格で再生成を開始したり、Codex app-serverを代理利用したりできない | 生成は認可された管理操作だから |
| `RA-13` | Google本人確認サービスのアプリ用資格情報 | 禁止 | 生成HTMLがアプリの認証手順を代理開始・完了して管理権限を得られない | 本人確認経路を権限取得に悪用させないため |
| `RA-14` | 匿名公開で現在公開中の版以外のHTML | 禁止 | 識別子の推測、履歴列挙、再利用用一時保存、古い参照などを使っても取得できない | `BR-012`と非公開化を成立させるため |

## 3. 利用者の種類による違い

| 観点 | 管理者プレビュー | 匿名公開 | 同じでなければならない結果 |
| --- | --- | --- | --- |
| 表示対象の選び方 | 管理者が閲覧を許可された形式検証合格版を選べる | 現在公開中の版だけに解決する | 解決後は1版のHTML本文と、必要性を個別に示した場合だけ`RA-02`を満たす最小の表示用情報を渡す |
| 管理者資格情報 | 周辺の管理操作には存在し得る | 存在しない | 生成HTML実行領域には渡らず、利用できない |
| 管理データ | 管理画面では閲覧できる場合がある | 原則として公開情報以外は見えない | 生成HTMLからは読書きできない |
| 外部通信 | 一律禁止しない | 一律禁止しない | アプリの資格情報・管理データを外部要求へ付けない |

管理者が見るHTMLだから安全と仮定してはならない。管理者プレビューは周囲に強い権限があるため、匿名公開より緩い隔離にしない。

## 4. 公開状態変更時の到達結果

| 事象 | 匿名閲覧者の到達結果 | 管理者プレビューの到達結果 |
| --- | --- | --- |
| 初回生成・未承認 | HTML本文へ到達不可 | 管理者が対象を選び、隔離表示で確認可能 |
| 公開承認 | 承認した版へ到達可能 | 管理者が許可された版を隔離表示で確認可能 |
| 公開中に新版を生成・保存 | 従来の公開版だけへ到達可能 | 新版を含む許可された合格版を隔離表示で確認可能 |
| 過去版へ公開切り替え | 切り替え後の過去版だけへ到達可能 | 許可された版を隔離表示で確認可能 |
| 非公開化 | 直前の公開版を含めHTML本文へ到達不可 | 版履歴は削除せず、管理者だけが隔離表示で確認可能 |

再利用用一時保存や古い参照がある場合でも、非公開化後の新しい匿名要求を旧公開版へ解決してはならない。一時保存の具体方式と失効方法は`L6`が本結果を満たすように決める。

## 5. 後続技術選定の合格条件

`L1-M1-S2`は、候補技術ごとに次を説明できる場合だけ、本境界を実現可能と判定する。

1. `RA-05`〜`RA-14`を、管理者プレビューと匿名公開の両方で禁止できる。
2. `RA-03`の外部通信を一律禁止せず、`RA-05`〜`RA-13`の情報を外部要求へ自動付与しない。
3. 表示対象解決とHTML実行を分け、HTML実行側が任意版や管理用永続化を選択できない。
4. 非公開化や公開版切り替え後に、匿名側の到達結果を新しい公開状態へ追従させられる。
5. 生成HTMLから管理者の周辺文脈へ直接・間接に戻る経路を遮断できる。
6. 採用技術だけでは保証できない項目を、後続`L6`の具体設計で必須化する条件として明示できる。

本作業は、上記を実現する具体的なWeb上の同一出所単位、接続先名、HTML表示実行主体、再利用用一時保存、所持者へ限定操作を許す証票、通信要求の付加情報、閲覧用アプリの制御を選ばない。

## 6. 受入試験へ渡す観測点

| 識別子 | 観測点 | 期待結果 |
| --- | --- | --- |
| `RO-01` | 管理者プレビューの生成HTMLが管理操作用の窓口の読取・変更を試みる | 管理データを取得できず、状態を変更できない |
| `RO-02` | 管理者プレビューの生成HTMLが管理者資格情報や親画面を読み取ろうとする | 値と画面状態を取得できない |
| `RO-03` | 匿名公開の生成HTMLが管理操作用の窓口・非公開版・履歴を取得しようとする | 取得できない |
| `RO-04` | 生成HTMLが管理対象外の外部試験サービスへ通信する | 通信が一律遮断されず、アプリ資格情報が要求に含まれない |
| `RO-05` | 公開中に未承認新版を保存する | 匿名側は従来版だけを取得する |
| `RO-06` | 公開を取り消した後に新しい匿名要求を行う | 直前の公開版を取得できない |
| `RO-07` | 推測した版参照や古い参照で匿名取得を試みる | 現在公開中ではない版を取得できない |

`L7`は実際の接続先名と実行環境を用いてこれらを自動検証する。試験で使う具体的な閲覧用アプリは受入証跡取得用の環境であり、特定製品・端末の保証を新設しない。
