# 共有論理モデル・識別子・不変条件

## 目的と範囲

論理モデルは、保存先やプログラムの型を決める前に、何を別の記録として区別し、どの関連を常に正しく保つかを定める設計である。この文書は後続のInterface仕様と論理Schemaが同じ概念を受け渡すために必要である。SQLの表、列、索引、HTTP形式、Repository、画面、認証・再試行・公開の具体的な状態遷移は定めない。

## 論理記録と関連

| 論理記録 | 表すもの | 必要な理由 | 許可する関連と禁止する関連 |
| --- | --- | --- | --- |
| HTML全体 | 一つの解説対象を管理し続ける親記録。 | 版、タグ、選んだ掲載先、公開中の版を同じ対象へ結び、版切替で管理状態を巻き戻さないため。 | 検証済み版・生成試行は0件以上、タグ付与は0件以上。現在の掲載先は0件または1件の`PlacementId`参照、公開版参照は0件または1件。配置をHTML全体の子記録として扱うこと、同時に二つ以上の`PlacementId`を参照することを禁止する。 |
| 検証済み版 | HTML形式の機械検証に合格した生成内容と、その系譜情報。 | 確認・履歴・公開の対象を失敗記録から分離し、保存内容を再現可能にするため。 | 必ず一つのHTML全体に属し、必ず一つの成功した生成試行から生じる。修正生成なら修正元版を0件または1件持つ。同じ版を二つ以上の試行が参照すること、保存後の変更・削除、別HTML全体への移動、タグ・配置の内包を禁止する。 |
| 生成試行 | 一回の生成実行の成功または失敗の要約。 | 生成サービス失敗と形式検証失敗を、利用者向けに安全な範囲で追跡するため。 | 必ず一つのHTML全体と、その同じHTML全体に属する一つの生成依頼に属する。一つの生成依頼には0件以上の試行を関連付けられる。成功し検証済み版が生まれた場合だけ、その版を0件または1件参照する。失敗試行が版・タグ・配置・公開版参照を持つことを禁止する。 |
| 生成依頼 | トピックと任意の追加生成指示、およびその入力が属するHTML全体。 | 何を求めて試行したかを、試行結果と分け、入力から試行、版までの系譜を一つの解説対象内で追跡するため。 | 必ず一つのHTML全体に属し、0件以上の生成試行を関連付けられる。トピックは必須、追加指示は任意。別HTML全体の生成試行との関連、固定項目への分解、対象トピックの独自制限を禁止する。 |
| タグ | 再利用できる分類名。 | 同じ分類名を複数のHTML全体へ付けられるようにするため。 | 名前は必須。単独では版・試行・公開版参照を持たず、タグ付与を介してHTML全体と関係する。 |
| タグ付与 | HTML全体とタグの現在の関連。 | タグを版の履歴から分離し、公開版変更後も維持するため。 | 一つのHTML全体と一つのタグを結ぶ。同一の組合せを重複させず、検証済み版がないHTML全体への付与を禁止する。 |
| 配置 | HTML全体から独立して作成する、任意名のサイト内掲載先。 | 一つの掲載先を複数のHTML全体で共有し、掲載先名をHTML全体ごとに複製しないため。 | 配置先名は必須。各HTML全体は現在の掲載先として0件または1件の配置を参照でき、同じ配置は0件以上のHTML全体から参照できる。版・試行へ直接属すること、配置を一つのHTML全体だけに属する記録とすることを禁止する。 |
| 公開版参照 | 閲覧者に表示する現在の検証済み版への参照。 | 公開中の旧版を新版の承認まで保持し、未公開を明示するため。 | HTML全体ごとに0件または1件。参照先は同じHTML全体の検証済み版だけ。失敗試行・未検証結果・他HTML全体の版への参照を禁止する。 |

## 識別子と参照規則

識別子は、同じ表示名や内容があっても機械的に別の記録として区別する値である。表示名やHTML本文を参照に使うと、改名・修正・同名作成で関連を誤るため、後続のInterfaceとSchemaは次の識別子を使う。

| 識別子 | 表す対象と必要な理由 | 許可する値・生成時点 | 参照規則と禁止事項 |
| --- | --- | --- | --- |
| `HtmlId` | HTML全体を一意に表す不変の識別子。版・生成依頼・試行・タグ付与・掲載先参照・公開参照を同じ対象へ結ぶために必要。 | HTML全体の作成時に一度だけ生成する、空でない値。値の具体形式は未決定。 | `Version`、`GenerationRequest`、`GenerationAttempt`、`TagAssignment`、`PublicationReference`は必ずこれを持つ。HTML全体は任意で一つの`PlacementId`を参照できるが、`Placement`自体は`HtmlId`を持たない。作成後の再利用・変更・別HTML全体への付け替えを禁止する。 |
| `VersionId` | 検証済み版を一意に表す不変の識別子。公開先、修正元、成功した生成試行を内容文字列に依存せず示すために必要。 | 検証合格後、版の保存時に一度だけ生成する、空でない値。 | 所属する`HtmlId`と、版を生じさせた成功した`GenerationAttemptId`の組で参照する。失敗試行へ発行しない。異なるHTML全体の版を修正元・公開先として参照すること、および二つ以上の試行が同じ`VersionId`を参照することを禁止する。 |
| `GenerationAttemptId` | 一回の生成実行を一意に表す識別子。失敗を含む試行の要約を重複なく追跡するために必要。 | 試行開始時に一度だけ生成する、空でない値。 | 一つの`HtmlId`と、その`HtmlId`を持つ一つの`GenerationRequestId`に属する。成功時だけ生成結果の`VersionId`を0件または1件参照できる。失敗時に`VersionId`を持つことを禁止する。 |
| `GenerationRequestId` | 同じ生成依頼を複数試行から区別する識別子。入力と実行結果を混同せず、試行と版の由来を同じHTML全体の中で追跡するために必要。 | 生成依頼の受理時に一度だけ生成する、空でない値。 | 必ず一つの`HtmlId`に属する。生成試行は必ず一つを参照でき、同じ依頼には0件以上の試行を関連付けられる。別の`HtmlId`を持つ試行からの参照、依頼の本文を識別子代わりに使うことを禁止する。 |
| `TagId` | タグという分類名の記録を一意に表す識別子。改名後も付与先を維持するために必要。 | タグ作成時に一度だけ生成する、空でない値。 | タグ付与は`HtmlId`と`TagId`の組を参照する。タグ名を関連の識別子に使うことを禁止する。 |
| `PlacementId` | 独立して作成する掲載先を一意に表す識別子。任意名の掲載先を複数のHTML全体から安全に共有し、名称ではなく安定した値で選択先を追跡するために必要。 | 配置の作成時に一度だけ生成する、空でない値。配置を参照するHTML全体がまだない場合にも生成できる。 | HTML全体は0件または1件の現在の掲載先としてこれを参照でき、同じ`PlacementId`は0件以上の`HtmlId`から参照できる。`PlacementId`が一つの`HtmlId`だけを参照するという制限、`VersionId`や`GenerationAttemptId`への所属、名称を参照識別子として使うことを禁止する。 |
| `PublicationReferenceId` | 公開版参照という現在の公開設定を一意に表す識別子。公開版の切替と未公開を版そのものから分けるために必要。 | 公開参照を作る時点に一度だけ生成する、空でない値。 | 一つの`HtmlId`と同じHTML全体に属する一つの`VersionId`を参照する。版ごとの承認済みフラグとして代用することを禁止する。 |
| `UserId` | 利用者を一意に表す識別子。管理者と閲覧者の権限判断を同名の人から切り離すために必要。 | 利用者を認識できた時点に生成または対応付ける空でない値。具体的な認証方式は未決定。 | 操作の主体を記録する必要がある場合だけ参照する。メールアドレス、セッション値、認証情報をこの識別子と同一視することを禁止する。 |

識別子の具体的な文字種、長さ、採番方式、永続化方式は物理設計で決める。ここでは、空でないこと、一度発行した識別子を別の対象へ再利用しないこと、参照先が存在し所属関係が一致することだけを共通制約とする。

## 系譜の規則

初回生成で得た検証済み版は修正元版を持たない。修正生成で得た検証済み版は、同じHTML全体に属する一つの修正元版を持つ。これにより、どの内容を直して得た結果かを辿れる。修正元版を複数持つこと、循環して自分自身または子孫を修正元にすること、別HTML全体の版を参照することは禁止する。

生成依頼は必ず一つのHTML全体に属し、生成試行は必ず一つの生成依頼に属する。生成依頼には0件以上の試行を関連付けられるが、その試行の`HtmlId`は依頼の`HtmlId`と一致しなければならない。したがって、同じ生成依頼を別のHTML全体の試行に使うことは禁止する。この関連は、入力、実行結果、検証済み版の由来が別の解説対象へ混ざることを防ぐために必要であり、修正元版の関連とは異なる。修正元版は生成内容を直す際の親版であるのに対し、生成依頼は何を生成したいかという入力である。

生成試行と検証済み版の関係は、成功した試行が0件または1件の生成結果の版を指す関係である。検証済み版が存在するなら、必ず一つの成功した試行がその版を参照し、二つ以上の試行が同じ版を参照してはならない。失敗試行は安全な失敗要約だけを残し、版を作らない。成功試行と版の一対一の由来を残すのは、版の内容の由来と失敗記録を混同せずに説明できるようにするためである。

配置はHTML全体から独立して作成する任意名の掲載先である。HTML全体は現在の掲載先として`PlacementId`を0件または1件参照でき、同じ`PlacementId`は0件以上のHTML全体から参照できる。これは、掲載先を作成することと既存の掲載先をHTML全体へ選ぶことを分け、共有する掲載先の名称や識別子をHTML全体ごとに複製しないために必要である。配置はタグと異なり、HTML全体ごとに一つだけ選ぶ掲載場所である。版は不変の生成内容、生成試行は一回の実行結果を表すため、配置を版または生成試行へ関連付けない。

## 不変条件

不変条件は、操作の前後を問わず常に守る規則である。具体的な操作手順を未決定のままでも、後続Taskが実装・Interface・Schemaで破ってはならない境界を共有するために定める。

1. 検証済み版はHTML形式の機械検証に合格した生成結果だけから作る。失敗試行、未検証結果、検証不合格結果は版にならない。
2. 検証済み版は保存後に不変であり、内容、`HtmlId`、`VersionId`、修正元版参照、およびそれを生じさせた成功した`GenerationAttemptId`を変更または削除しない。
3. 失敗生成試行は利用者向けの成功・失敗と失敗理由の要約を保持するが、詳細な内部ログ、タグ、配置、公開版参照、生成結果の版参照を持たない。
4. タグ付与と配置はHTML全体にだけ属し、版にも生成試行にも属さない。公開版を切り替えても、これらの現在状態を過去の版時点へ戻さない。
5. タグ付与と配置は、少なくとも一つの検証済み版を持つHTML全体にだけ許可する。検証失敗記録へタグまたは配置を付けない。
6. 公開版参照はHTML全体ごとに0件または1件だけであり、参照先は同じHTML全体の検証済み版である。0件は未公開を表す。
7. 新しい検証済み版が作られても、公開版参照は自動でその版へ変わらない。新しい版が公開対象として承認されるまで、既存の参照があれば旧版を維持する。
8. 公開版参照がないHTML全体は閲覧者へ公開しない。公開参照の有無は版の不変性やタグ・配置の現在状態を変更しない。
9. 管理者は初期リリースで一人だけを想定し、閲覧者は公開版だけを閲覧できる。具体的な本人確認と許可判定の方式はこのモデルに含めない。
10. 生成HTMLは外部通信を一律に禁止しない一方、アプリの認証情報と管理データへアクセスさせない。この表示隔離の実現方式は後続Taskが定める。
11. 生成依頼は必ず一つの`HtmlId`に属し、各生成試行は必ず一つの`GenerationRequestId`と、その依頼と同じ`HtmlId`に属する。依頼を別HTML全体の試行へ関連付けない。
12. 生成試行が`VersionId`を参照できるのは成功した場合だけであり、参照できる版は0件または1件である。検証済み版は必ず一つの成功した生成試行から生じ、同じ`VersionId`を二つ以上の試行が参照しない。
13. 配置はHTML全体から独立して作成する。各HTML全体が現在の掲載先として参照できる`PlacementId`は0件または1件であり、同じ`PlacementId`は0件以上のHTML全体から参照できる。配置を一つのHTML全体だけに属する記録とすること、版・生成試行へ関連付けること、HTML全体が複数の配置を同時に参照することを禁止する。

## 後続Taskへの引渡し

L1-M2-S2は、この文書の記録名、識別子、任意性、参照制約、不変条件を技術非依存のInterfaceとMock例へ写す。L1-M2-S3は、同じ概念を論理Schemaの永続・一時対応表へ写す。どちらも物理形式や状態遷移をこの文書から推測して追加してはならない。
