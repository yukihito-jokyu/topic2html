# 機能要件

すべての情報源はGitHub issue #87、状態はconfirmedである。

## 入力と生成

| ID | 要件 |
| --- | --- |
| REQ-001 | 管理者は自然言語のプロンプトで解説HTML生成を依頼できる。 |
| REQ-002 | 有効な生成プロンプトには、解説対象のトピックを含める。 |
| REQ-003 | 表現方法や重点などの指示は任意で含められる。 |
| REQ-004 | 初期リリースの生成にはCodex app-serverを使用する。 |
| REQ-005 | 生成結果を版として扱う前にHTML形式を機械的に検証する。 |
| REQ-006 | 管理者はHTML形式に合格した各版をWebアプリで確認できる。 |
| REQ-007 | 管理者は合格済み版へ自然言語の修正指示を与え、新しい結果を生成できる。 |
| REQ-008 | 修正による生成結果にも初回と同じHTML検証を行う。 |

## 生成失敗時の処理

| ID | 要件 |
| --- | --- |
| REQ-009 | 生成結果を取得できない場合とHTML検証に失敗した場合は、同じ失敗フローで扱う。 |
| REQ-010 | 失敗後は自動で最大3回再生成する。 |
| REQ-011 | 自動再生成がすべて失敗したら最終エラーを表示して停止する。 |
| REQ-012 | 自動処理終了後、管理者は新たな生成処理を開始できる。 |
| REQ-013 | 各生成試行の結果を記録する。 |
| REQ-014 | 管理者が次の対応を判断できる安全な失敗理由の要約を表示する。 |

## 版と公開

| ID | 要件 |
| --- | --- |
| REQ-015 | HTML形式に合格した初回・修正結果を、それぞれ別版として保存する。 |
| REQ-016 | 管理者は履歴を確認し、任意の合格済み版をプレビューできる。 |
| REQ-017 | 管理者は未承認の合格済み版を現在の公開版として承認できる。 |
| REQ-018 | 過去の合格済み版を公開版に選択すると、その版を承認する。 |
| REQ-019 | 管理者は解説コンテンツを非公開にできる。 |
| REQ-020 | 閲覧者はGoogleログインなしで現在の公開版を閲覧できる。 |

## 整理

| ID | 要件 |
| --- | --- |
| REQ-021 | 管理者はタグを作成できる。 |
| REQ-022 | 管理者はタグ名を変更でき、変更後の名前はすべての関連コンテンツへ反映される。 |
| REQ-023 | 管理者は条件を満たす解説コンテンツにタグを付与・解除できる。 |
| REQ-024 | 管理者は任意名の掲載場所を作成できる。 |
| REQ-025 | 管理者は条件を満たす解説コンテンツに掲載場所を設定できる。 |

## 権限と隔離

| ID | 要件 |
| --- | --- |
| REQ-026 | 事前登録済みGoogleメールアドレスだけが管理操作を行える。 |
| REQ-027 | 管理者以外は生成・管理操作を行えない。 |
| REQ-028 | 管理者プレビューと公開表示のどちらでも、生成HTMLをアプリケーションから隔離する。 |
| REQ-029 | 過去または推測した参照先から、非公開の版や管理記録を取得できないようにする。 |
| REQ-030 | 生成HTMLの外部通信は許可するが、アプリの資格情報、管理者セッション、秘密値、管理データを付与しない。 |
