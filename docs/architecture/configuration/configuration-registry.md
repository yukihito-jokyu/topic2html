# 設定情報の分類台帳と露出境界

## 1. この文書の目的と適用範囲

設定情報とは、同じプログラムでも配置先・実行環境・接続先によって変える値であり、ソースコードへ埋め込まない値を指す。本台帳は、各値を誰が読むか、どの画面や成果物へ渡してよいか、記録してよいかを実装前に固定する。値の種類を区別しなければ、公開画面や生成HTMLへ資格情報を混入させたり、必要なサーバー設定を利用できなくしたりするためである。

本書は値の発行、秘密管理製品への保存、実行環境への注入、更新（Rotation、漏えい時などに値を置換する運用）、Google OAuth（Googleが本人確認を委任する認可方式）の画面設定、Codex app-server接続の実装を決めない。これらは後続Taskが本書の露出制約を入力として具体化する。生成HTMLの外部通信も一律には禁止しない。外部通信を許容しつつアプリ資格情報を自動付与しない条件は、[横断信頼境界](../trust-boundaries/cross-cutting-trust-boundaries.md)の`TB-07`に従う。

## 2. 分類軸と共通規則

### 2.1 機密区分

機密区分は「値を知った第三者が何をできるか」を表す分類であり、「どの処理が読むか」を表す利用主体とは混ぜない。利用主体と露出面を別の列にすることで、例えばサーバーだけが読む公開可能設定と、サーバーだけが読む秘密値を区別できる。

| 区分 | 意味と該当条件 | 該当しないもの・境界 | 必要な理由 |
| --- | --- | --- | --- |
| 公開可能設定 | 値単体を公開画面、ブラウザの管理画面、生成HTML、文書へ出しても、認証・認可・保存領域への権限を新たに与えない値。例は表示用の固定名や、秘密を含まない公開URLである。 | 「画面で使う」だけでは公開可能にしない。値が接続権限、利用者識別、内部構成の攻撃容易化へ結び付く場合はサーバー限定設定または秘密値にする。 | クライアントに渡せる値を明示しないと、実装者が安全性を推測で判断することになる。 |
| サーバー限定設定 | 権限そのものではないが、利用者の識別、内部接続先、実行方針、資源上限などを表し、サーバープロセスだけが読む値。 | パスワード、署名鍵、アクセストークン、資格情報を含むURLは秘密値であり、この区分ではない。 | 公開可能設定と区別することで、不要な構成情報をブラウザや生成HTMLへ出さない。 |
| 秘密値 | 知るだけで本人・サービスになりすましたり、保存領域・セッション・外部サービスへ接続したりできる値。 | 値が偽物で、外部サービスや実データへ到達できないTest用代替値は実秘密値ではない。ただし実秘密値に似た文字列をFixtureへ置くことは許可しない。 | 一つでも露出すれば、表示領域を隔離しても管理制御領域への到達が可能になるため。 |
| Test用代替値 | Testだけで使う、実環境の認証・保存領域・外部サービスへ到達しない決定的な値。決定的とは、同じ入力なら同じ結果を再現できる性質である。 | 実環境のClient secret、Database URL、Session署名鍵のコピーや、偶然有効になり得る共有資格情報は代替値ではない。 | 自動検証には値が必要だが、実秘密値をFixture（検証用の固定入力）へ複製しないため。 |

### 2.2 露出面

露出面は値を読める場所または記録として残り得る場所である。許可は「必ず渡す」ではなく、目的に必要な場合に限る上限である。禁止は、値の形式や難読化の有無に関係なく渡してはならないことを表す。

| 露出面 | 意味 | 共通の禁止・必要な理由 |
| --- | --- | --- |
| Server | 管理API、公開表示の解決、Migration Runnerなどを実行するアプリ側プロセス。 | Serverが読めることは、ブラウザや生成HTMLへ転送してよい根拠にならない。権限を持つ処理を最小化するためである。 |
| 管理画面 | 管理者がブラウザで操作する画面。管理者向けであっても、ブラウザから読める値は利用者端末・開発者ツール・画面撮影で複製され得る。 | 秘密値、サーバー限定設定、認可判断の根拠を渡さない。管理者の高い権限を表示コンテンツへ伝播させないためである。 |
| 公開画面 | ログインしていない閲覧者を含む画面。 | 公開可能設定以外を渡さない。匿名閲覧を管理情報の閲覧へ拡張しないためである。 |
| 生成HTML | Codex app-serverが返した、または管理者が閲覧するHTMLの実行領域。内容は信頼しない。 | いかなる秘密値、サーバー限定設定、認可結果、管理操作用窓口も渡さない。`TB-05`と`TB-06`の隔離を守るためである。 |
| Test Fixture | 自動検証が読む固定の入力・期待結果。 | Test用代替値だけを許可し、実値と似た接続文字列を置かない。公開Repository、CI出力、失敗時表示へ複製され得るためである。 |
| 文書・Log・CI Artifact | 設計書、実行記録、標準出力・エラー出力、継続的インテグレーションの保存物。CI Artifactは検証実行後に保存・共有されるファイルである。 | 値そのものは公開可能設定だけを条件付きで記録できる。サーバー限定設定は原則として値を記録せず名称・分類・有効性だけ、秘密値は常に記録禁止とする。記録物は保持期間と閲覧者が広がるためである。 |

## 3. 設定・秘密情報台帳

この表の「供給元」は値をどこから受け取るかの設計上の境界であり、具体的な秘密管理製品や注入コマンドを選ぶものではない。「記録可否」は値そのものの記録可否であって、設定名、機密区分、存在・形式検証の成功/失敗理由を記録することは禁止しない。

| 識別名と表す値 | 区分 | 供給元 | 利用主体 | 許可された露出面 | 記録可否 | 必要な理由と条件 |
| --- | --- | --- | --- | --- | --- | --- |

## 4. 受渡しの判定規則

### 4.1 Serverから各表示面への受渡し

1. Serverが値を読む前に、台帳の識別名、機密区分、利用主体と一致することを確認する。未知の設定は、公開可能と仮定して表示せず、設定不備として拒否する。未知値を黙って渡すと、新しい秘密値が分類前に漏れるためである。
2. 管理画面へは、公開可能設定だけを目的がある場合に渡せる。Server限定設定と秘密値は、設定済みか・形式が正しいか・許可されたかという結果だけを渡す。結果と元の値を分けることで、診断可能性と非露出を両立する。
3. 公開画面へは、公開可能設定だけを目的がある場合に渡せる。管理者だけが見る値であっても、公開画面の応答へ混入させない。
4. 生成HTMLへは、台帳に明示した公開可能設定のうち、HTML表示に不可欠な値だけを渡せる。現在は`PUBLIC_DISPLAY_NAME`がその候補であり、`GOOGLE_OAUTH_CLIENT_ID`は生成HTMLに不要なので禁止する。HTMLの内容を信頼しないため、公開可能設定であっても最小化する。

### 4.2 設定不備時の停止

Server限定設定または秘密値が必要な処理は、値が未指定、不正形式、空文字、複数値、区分外の露出面から受け取った値のいずれかなら開始しない。失敗通知には識別名と安全な原因分類だけを使い、値、URL全体、鍵の一部、接続文字列を含めない。これにより設定漏れを早く発見しながら、診断Logを新たな漏えい面にしない。

Migration Runnerは、`MIGRATION_DATABASE_URL`、Database側10秒、呼出側15秒の検証に失敗した場合、Migrationを1件も実行しない。Database側の待機上限が呼出側より短いことは、`ADR-0005`が定めた「先にDatabase側で安全停止する」条件である。値を変更する後続設計は、両方が有限で、Database側 < 呼出側という関係を維持し、競合Integration Testで確認しなければならない。

## 5. 後続Taskへの入力と未決定事項

後続Taskは、本台帳の識別名を新しい実装上の変数名へ置き換えてはならない。変数名を追加する場合は、どの台帳項目を具体化するか、区分、利用主体、露出面、記録可否を同時に記録する。これは設定雛形、認証、Migration、Codex接続の実装がそれぞれ別の分類を作って矛盾することを防ぐためである。

本Taskの開始時点で直接の後続Issueを特定する接続台帳がないため、本書は特定の受渡し先や着手可否を宣言しない。後続を管理するOwnerは、接続台帳を作成または復元するとき、本書を入力として利用するTaskと、そのTask固有の他依存を分けて記録する必要がある。今回の文書が渡せることと、他の依存Taskを含めて後続が着手できることは別の判定だからである。
